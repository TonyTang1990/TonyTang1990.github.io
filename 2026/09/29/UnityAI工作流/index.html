前言

随着AI越来越强大，纯AI参与制作的流程(AI Vibe Coding，AI自动拼UI，AI自动生图，AI自动生成Psd分层等)越来越多。虽然Unity 6已经推出了官方AI和CLI等AI相关工具，但目前国内使用Unity官方AI有很多门槛限制，所以本章节主要以使用第三方Github的unity-mcp+Codex的方式去搭建AI自动化流程。

本章节主要研究一下几个问题：

  1. AI自动拆分效果图(解决UI图片资源快速生成问题)
  2. AI自动拼UI(节省拼UI时间，提升开发效率)
  3. AI生成UI逻辑代码(节省些基础UI代码逻辑的时间，提升开发效率)

MCP for Unity

Unity MCP是通过使用Model Context Protocol协议让Unity Editor担任一个Server的角色，然后暴露工具，场景管理，脚本编辑，Console数据读取等能力给AI。

MCP for Unity 通过 Model Context Protocol 把 Claude、Cursor、VS Code、本地大模型等 AI 助手接入 Unity 编辑器，让它们直接帮你管理资源、搭场景、写脚本、跑测试，把开发流程里的重复活儿都包了。

从介绍可以看出，要想让CodeX，Claude Code之类的AI工具能访问Unity像人一样去使用Unity工具或者暴露的接口去做事，我们首先需要接入Unity MCP，这样AI工具才能和Unity通信使用对应工具做事。

Unity for MCP会给我们提供一下工具能力(以下说明来源getting-started):

  • 40+ Unity Editor tools exposed over MCP — manage_scene, manage_script, manage_gameobject, manage_material, manage_physics, run_tests, and more.(通过MCP暴露很多Unity编辑器工具支持操作场景，脚本，GameObject，材质，物理，执行测试等)
  • 25+ read-only resources for state introspection — editor_state, gameobject_components, project_info, unity_instances, etc.(能只读部分GameObject组件数据，项目信息等)
  • Auto-configuration for popular MCP clients — Claude Desktop, Claude Code, Cursor, VS Code, Windsurf, Cline, Codex, Qwen, Gemini CLI, Copilot CLI, OpenClaw.(能自动配置适配常规AI工具，比如Codex)
  • Multi-instance support — drive several Unity Editors from a single session via set_active_instance.(单对话能驱动多个Unity编辑器实例)
  • Two transports — HTTP (multi-agent, default) and stdio (single-agent legacy).(支持HTTP和stdio通信方式)

  1. Unity版本Unity 2021.3 LTS or newer
  2. Python版本Python 3.10+ with uv

自定义MCP for Unity工具

实际开发项目过程中，只使用MCP for Unity提供的自带工具还不满足需求，比如我们要想支持打包工具的调用。

  1. 首先我们需要再Editor下定义一个静态class且需要定义McpForUnityTool标签**
  2. 然后定义一个Class作为工具类型，工具类型里定义工具参数成员，工具参数成员必须带上ToolParameter属性标签
  3. 带McpForUnityTool标签的静态class定义静态方法HandleCommand(JObject params)方法进行工具调用处理，需要返回SuccessResponse类表示成功，ErrorReesponse表示出错

可以看到MCP for Unity已经自动检测到了我们定义的自定义工具，接下来我们去Codex测试主动使用自定义工具触发打包。

可以看到我们成功使用Codex自然语言驱动调用了我们给MCP for Unity定义的自定义打包工具，打包参数也和我们描述的一样，日志正确。

AI自动拆分效果图

一般工作流是我们从美术那里得到效果图(png)资源，美术将切个好的单个元素图片也给我们，让我们利用所有单个图片元素和效果图进行UI窗口效果还原。

而AI自动拆分效果图这一步主要是解决我们得到效果图(无论是美术给的还是AI自动生成的)，我们直接利用AI实现自动拆分单个元素图片，当我们把单个元素图片拆分得到后，我们才能进行下一步UI拼接效果图还原。

切图工具制作

根据AI的说法要想实现快速根据效果图自动切割拆分图片元素，且实现切割图片元素宽高是2或者4的倍数，要求切割的图片元素尽量少留空白，同时切割元素空白部分用透明提到，导出单张图片格式统一为png这个功能，我们需要先让AI制作一个能实现上述切割需求的脚本工具。

可以看到生成的工具启动入口是crop.ps1这个是PowerShell的脚本程序，为了方便跨平台我后续又让AI优化成纯Python的版本:

重用已有UI预制件拼UI

但真实开发环境中，我们不仅仅是让AI自己用最原始的组件进行效果图还原，我们还会开发很多通用预制件，很多效果图对应部件都应该使用对应通用预制件制作而非使用原始组件拼接，那么如何让AI知道我们的通用预制件和使用规则进行UI自动拼接了？

AI给的思路是在自动拼UI的Skill里添加已有预制件服用规则描述，让自动拼UI前先去读取AGENTS.md里指定的UI预制件目录表描述信息和规则。UI预制件目录表里会有详细当前项目预制件的信息介绍供AI读取。AI自动UI时就会优先使用符合的已有预制件进行UI制作拼接还原。
